# Use with AI agents

FlaUI for Python ships three things for AI coding agents and computer-use agents:

- **Agent skills.** Four short guides that teach an agent to set up FlaUI, find and drive
  elements, write UI tests and debug flaky automation. They come as a plugin for **Claude Code**
  and **OpenAI Codex**.
- **`llms.txt` and `llms-full.txt`.** A link index and the full documentation as one Markdown file,
  for any tool that reads them.
- **A typed Python API** that maps cleanly onto agent tools. See [Building agent tools](#building-agent-tools).

## The skills

| Skill | Teaches the agent to |
|-------|----------------------|
| `flaui-setup` | Install the package, call `setup_pythonnet_bridge()` before any C# import, choose UIA2 or UIA3, launch, attach and dispose. |
| `flaui-find-and-act` | Build conditions with the `ConditionFactory`, choose a find scope, use XPath, convert with `as_*`, prefer UIA patterns over the mouse, use `post_wait` and `Retry`. |
| `flaui-write-tests` | Write pytest UI tests: the bridge in `conftest.py`, session fixtures, element name maps, enum assertions, `expect()`, and this project's UIA2/UIA3 x WinForms/WPF matrix. |
| `flaui-debug-flaky` | Work through bridge and DLL errors, `ElementNotFound`, timing races, focus problems, known platform limitations, C# logging and failure screenshots. |

The skills live in
[`plugins/flaui/skills/`](https://github.com/amruthvvkp/flaui-uiautomation-wrapper/tree/master/plugins/flaui/skills).
Each one is a folder with a `SKILL.md` in the [Agent Skills](https://agentskills.io/) format. Every
Python snippet in them is copied from a runnable file under `examples/`, and a unit test fails if a
snippet or a `flaui.*` name drifts from the code.

Agents load a skill when your request matches its description. In Claude Code you can also call
one by name, for example `/flaui:flaui-setup`. In Codex, mention it with `$`.

## Claude Code

The repository is a Claude Code plugin marketplace. In a Claude Code session, add it and install the
`flaui` plugin:

```text
/plugin marketplace add amruthvvkp/flaui-uiautomation-wrapper
/plugin install flaui@flaui-uiautomation-wrapper
```

From a terminal, the same steps are:

```powershell
claude plugin marketplace add amruthvvkp/flaui-uiautomation-wrapper
claude plugin install flaui@flaui-uiautomation-wrapper
```

- To share the plugin with your team, install with `--scope project`. This records it in the
  project's `.claude/settings.json`, which you commit.
- The plugin version follows the package version. To pick up a new release of the skills, run
  `/plugin marketplace update flaui-uiautomation-wrapper`.

## OpenAI Codex

The repository is also a Codex plugin marketplace (`.agents/plugins/marketplace.json`). Add it, then
install the plugin:

```powershell
codex plugin marketplace add amruthvvkp/flaui-uiautomation-wrapper
codex plugin add flaui@flaui-uiautomation-wrapper
```

You can also browse and toggle it from `/plugins` inside Codex. Start a new session afterwards so
the skills load. Run `codex plugin marketplace upgrade flaui-uiautomation-wrapper` to refresh.

### Without the plugin

Codex, and other agents that read the Agent Skills format, also load skill folders straight from
disk:

- **For one project:** copy the folders from `plugins/flaui/skills/` into `.agents/skills/` at your
  repository root. Codex finds them there, and your team gets them with the repository.
- **For every project:** copy them into `~/.agents/skills/`.
- **With Codex's built-in installer:** ask `$skill-installer` to install
  `plugins/flaui/skills/flaui-setup` (and the others) from the repository
  `amruthvvkp/flaui-uiautomation-wrapper`, ref `master`.

## llms.txt

The docs site publishes the [llms.txt](https://llmstxt.org/) files at its root:

| File | What it holds |
|------|---------------|
| [`llms.txt`](https://amruthvvkp.github.io/flaui-uiautomation-wrapper/llms.txt) | An index: a summary, key facts, and one line per docs page. |
| [`llms-full.txt`](https://amruthvvkp.github.io/flaui-uiautomation-wrapper/llms-full.txt) | All the docs in one Markdown file. Snippets are expanded from `examples/`, and the API reference is rendered from the docstrings. |

Each published docs version has its own copy at its own root, for example
`https://amruthvvkp.github.io/flaui-uiautomation-wrapper/latest/llms.txt`. The links inside each
copy point at that version.

Give `llms.txt` to an agent that can fetch pages on demand. Give `llms-full.txt` to a tool that wants
everything in one context, such as a chat upload, a RAG index or an IDE docs source. The files are
generated by `scripts/build_llms_txt.py` on every docs build, so they always match the site.

## Building agent tools

The library makes a good base for agent tools. Elements, patterns and input are plain Python calls
with pydantic types, so wrapping `find`, `click`, `type` and pattern actions as
[MCP](https://modelcontextprotocol.io/) tools, or any other tool interface, takes little code. An
agent can then drive any Windows application.

A first-party MCP server is planned. Its progress is tracked in
[#143](https://github.com/amruthvvkp/flaui-uiautomation-wrapper/issues/143) and on the
[Roadmap](roadmap.md).

!!! warning "Responsible use"

    An agent that clicks and types into live applications can do real damage. Only automate
    applications and machines you are allowed to control. Scope tools to a known window or process
    rather than the whole desktop, and keep a person in the loop for anything that cannot be undone.
    See the [Agentic Guidelines](agentic-guidelines.md#use-with-ai-agents-and-mcp).
